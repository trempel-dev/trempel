# Trempel — project context

Лёгкий agent-first 2D-движок на PixiJS. Монорепа (npm workspaces): `@trempel/scene` 2.3.0, `@trempel/kit` 2.3.0, `@trempel/slot` 2.3.0 (версии синхронны; шаблоны следуют за китом):
- `packages/scene` — `@trempel/scene`: формат сцен как валидный SVG (+ namespace `tml:`), рантайм, плеер анимаций, ядро редактора (команды базы, клипов `clip.*`/`track.*`/`key.*`/`event.*`, эффектов наследника `heir.*`) и страница редактора (таймлайн, инспекторы потребителя, мост агента `trempel-edit`);
- `packages/kit` — `@trempel/kit`: кит игр поверх сцен (`createGame` — сборка модулей `src/game/`: типы, сейв, раскладка, сцены; сервисы — контракты с обязательным моком, `src/services/`; платформы web / YouTube Playables / mock — реализации платформенных контрактов, цикл, экраны и попапы, раскладка, UI-компоненты и скины, звук, частицы (эффект — узел сцены `tml:type="fx"`; редактор частиц — инспектор `fx` страницы редактора через `kitView`), хореография данными (`src/choreo/`), импорт анимаций (Spine, Unity, частицы Unity/Cocos), сейв, гейты сборки; дефолтный скин — `skins/default/ui`, коллекция `npm:@trempel/kit/skins/default/ui`);
- `packages/slot` — `@trempel/slot`: слот поверх кита = вьювер раундов. Лента раунда (`@trempel/slot/feed`: типы, `planRound` — книга раунда, чанкер только по маркеру `step`, деньги в кредитах ставки, громкие `E_FEED`; игровые трансформы и флаги шагов — сквозь, к игре: `extend`, события `extra`), источники `RoundSource` (`fixtureSource` / `httpSource` / `fnSource`), плеер `RoundPlayer` (события книги → последовательности хореографии кита по таблице привязок из данных игры, хуки для своих событий), действия `reels:*` / `lines:*`, барабаны pixi-reels как компонент сцены, стандартный наследник HUD и попапы; формат ленты — `packages/slot/docs/feed.md`. Математики в ките нет и не будет (выигрыши, ленты, RTP считает тот, кто делает ленту);
- `templates/casual` — стартовый шаблон казуалки на ките (private, не публикуется); монеты — на сервисе `wallet`;
- `templates/slot` — шаблон слота с линиями на `@trempel/slot` (private): всё данные — `slot.json` (3×3) и `slot.5x3.json` (5×3: сетка, линии, wild → множитель, marks/tease, ставки, источник, привязки), базовая хореография жанра `choreo/*.md` (`spin.start`, `spin.stop`, `reel.stop`, `anticipation`, `wild.expand`, `lines.show`/`lines.cycle`, `win.count`, `bigwin.<уровень>`, `scatter.hit`, `idle`, `quickstop`, `skip`, крючки персонажа `character.*`; `consts.md` — режимы скорости), `sounds.json`, синтетические фикстуры (`scripts/fixtures.mjs`, руками; `fixtures/`, `fixtures/5x3/`), скины `skins/default` (поле любой сетки, персонаж-заглушка) и `skins/fruity-spin` (только 3×3, без персонажа) (`symbols.json` — буквы ленты → арт).

Пакеты ссылаются друг на друга **только по имени** (`@trempel/scene`, `@trempel/kit`, `@trempel/slot`), относительных импортов между пакетами нет — любой выносится `git filter-repo --subdirectory-filter` без правки кода. Ниже пути `src/`, `editor/`… — внутри `packages/scene`, если не сказано иначе.

## Спека
Единственный источник истины по формату — `packages/scene/docs/format/scene-format.md` (формат v1.3, пакет 2.3; §15 — публичный API, §16 — коды ошибок, в конце — changelog). Её примеры (блоки `svg`/`xml`/`md`/`mdz`) — тесты (`test/spec.test.ts`; `error=E_CODE` — пример, который обязан упасть этим кодом): спеку правят вместе с кодом. Двухдокументная модель: стерильная база `X.svg` (ванильный SVG) + наследник `X.tml.svg` (`tml:extends` / `<tml:ref>` / `tml:insert`) + контракт `X.contract.xml`; клипы — md-клипы (`anim/*.md`, `X.anim.md`) → anim.json. Миграция потребителей по версиям — `MIGRATION.md` (§10 — переход на имена Trempel, §11 — коллекции, §12 — 1.2: без встроенных компонентов, монорепа; §13 — 2.0: узкий вход, коды сообщений, формат 1.3). Коллекции: `@имя/путь` → папка из `.trempel/project.mdz` корня проекта (`src/href.ts`, `src/project.ts`, Node — `src/node/project.ts`); наследник проекта (1.3): любой `*.tml.svg` проекта с `tml:extends` на документ коллекции ложится слоем на все его инстансы (`MountOptions.heirs`, Node-инструменты находят сами, кит — через плагин). Scope строгий: в формат идёт только то, что нужно реальным сценам; партиклы, plist, экспорт чужих форматов, layouts, inputs, foreach, themes — не делать (партиклы, раскладка экранов, ввод — дело кита, не формата).

## Совместимость
Старые имена формата (префикс, наследник, модуль просмотрщика, папка редактора) читаются один релиз с предупреждением — весь этот слой в `src/compat.ts` (+ `test/compat.test.ts`); конвертер — `scripts/migrate-tml.mjs`. Больше нигде старые имена не упоминаются. API без алиасов.

## Сообщения и API
- Всё, что видит пользователь пакета (ошибки, предупреждения, CLI, UI просмотрщика и редактора), — на английском и начинается с кода: `E_CODE: message` / `W_CODE: …`. Каталог — `src/codes.ts` (код → описание); новый код — туда, затем `npm run error-codes` (раздел §16 спеки и `src/code-names.ts` — имена для рантайма, описания в бандлы игр не идут; `test/codes.test.ts` сверяет). Место в сообщение — через `within(place, msg)` (код остаётся первым). Тесты сверяют коды (`test/helpers/codes.ts`), не тексты. Кириллица в строковых литералах `src/ editor/ edit/ view/` запрещена тестом (`test/english.test.ts`); комментарии — можно.
- Stable-вход сцены — `src/core.ts` (+ `index.ts` с PixiBackend): только список §15 спеки. Всё остальное — `@trempel/scene/internal/<модуль>` (`exports ./internal/*` → `dist/*`), без обещаний стабильности; кит и редактор берут оттуда. Кит 2.0 — так же: `@trempel/kit` = `createGame` с опциями/типами, типы членов `Game` (только типы), сервисы, компоненты/скин; плюс `/vite`, `/testing`, `/e2e`, `/skin-cli`; остальное — `@trempel/kit/internal/<модуль>` (таблица — CHANGELOG кита 2.0.0). `<!DOCTYPE>`/`<!ENTITY>` в документах формата — `E_DOCTYPE`.

## Toolchain
Node 22.6+ (scene сам по себе — 20+), TS 5.x strict, ESM. Dev-инструменты — один набор в корне: Vite 6 (dev-страницы scene — `resolve.preserveSymlinks: true`), Vitest 3 (`test.projects` в `packages/scene/vite.config.ts`: `unit` / `e2e`), TypeScript 5, Playwright, `@types/node` 22; `overrides` — одна копия `pixi.js` (8.22.0) и `sharp` (^0.34.5). pixi.js — peer `^8.19.0` у scene, kit и slot. Ядро тестируется без браузера через инъекцию (mock clock, mock renderer — `test/helpers/mockBackend.ts`). Кит импортирует сцену из её `dist`, слот — кит из его `dist` — корневые `typecheck`/`test` сначала собирают `@trempel/scene` и `@trempel/kit`.

## Команды (из корня)
- `npm run build` — scene (tsc → `dist/`: core, index, editor, node + библиотека страницы редактора `dist/edit`), затем kit (`scripts/ui-scenes.mjs` → `src/ui/scenes.ts`, tsc), затем slot (tsc); `npm run build:browser` — браузерные бандлы `dist/browser/trempel*.js` (scene)
- `npm test` — unit всех пакетов (vitest, без браузера); `npm run test:e2e` — scene: редактор и `view:shot` в headless Chromium (по одному файлу, машинный лок `os.tmpdir()/trempel-e2e.lock`, `TML_E2E_LOCK` переопределяет); шаблоны casual и slot: сборки web и YouTube (+ гейты Playables) и Playwright; у слота — гейт рескина: все фикстуры через каждый скин (`?skin=`) + `view:shot` сцен и попапов каждого скина
- `npm run typecheck`
- CI — `.github/workflows/ci.yml` (push/PR в `main`, + ветка `ci-check` для прогонов): build, typecheck, test, test:e2e, visual-gate.
- прокси в `packages/scene` (пути — от корня, `INIT_CWD`): `npm run view -- <папка>` — просмотрщик сцен (`view/`; в пакете — только как бин `trempel-view`: `npx @trempel/scene view:shot …`, Vite/Playwright — опциональные peer); `npm run view:shot -- <сцена> --out x.png [--settle 2]` — headless-снимок + JSON ошибок, детерминированный (виртуальные часы Playwright: время идёт только шагами 1/60 с, `--settle` секунд после монтирования; бит в бит между прогонами); `npm run visual-gate [-- --update]` — снимки примеров против `test/golden/*.png` (≤ 1/255 в среднем; гейт CI); `npm run edit -- <папка>` — страница редактора на dev-сервере (`edit/`; как библиотека — `@trempel/scene/edit`: `mountEditor` + `SceneIO` хоста); `npm run check -- <папка | X.svg> [--anim anim/x.md]` — чекер сцены и клипов; `npm run flatten -- <сцена> --out x.svg [--embed]` — сцена → ванильный SVG (`src/flatten.ts`, CLI `src/node/flatten-cli.ts`); `npm run anim:compile -- anim/x.md [--tex "art/{}.png"]` — md-клипы → json; `npm run dev` — vite, примеры `examples/*/index.html`
- `node packages/scene/scripts/migrate-collections.mjs <папка>` — относительные ссылки → `@имя/…`
- `@trempel/scene/editor` — ядро редактора (`editor/`, README там); `npm run editor:commands` — пересобрать список команд (и команд клипов) в `editor/README.md` и `edit/API.md`
- мост агента к открытой странице редактора (`npm run edit`): `npx trempel-edit eval [--port 5181] '<code>'` / `save` / `state` / `mcp` (MCP по stdio) — `POST /__tml/agent` dev-сервера → `tml.run` в странице (одна запись undo)
- kit: `trempel-skin <папка скина>` — замер арта скина в `skin.json`; `trempel-fx-import <Unity-проект | префаб | сцена> --out <папка> [--compare old.json]` — частицы Unity (YAML, вложенные префабы, материалы/текстуры по GUID) → `effects.json` + PNG + отчёт auto/manual/hard (`src/fx-import/`), `--cocos <plist | json | папка>` — частицы Cocos; `trempel-spine-import <скелет.json | папка> [--out] [--atlas] [--frames …]` — Spine → `scene.svg` + md-клипы + `art/` + `report.md` со сверкой (`src/spine-import/`, корпус — `TREMPEL_SPINE_CORPUS`); `trempel-anim-import <Unity-проект | префаб | .controller | .anim> --out <папка> [--scene X.svg] [--map anim-map.md]` — AnimationClip/Animator → md-клипы со сверкой (`src/anim-import/`, корпус — `TREMPEL_UNITY_CORPUS`); общее импортёров клипов — `src/clip-import/`; `npm run view -- packages/kit/ui/scenes` — экраны кита и витрина эффектов (`effects`) в просмотрщике

## Инварианты
- Никакой игровой специфики в `packages/scene/src/` — формат общий, встроенных компонентов нет (`createDefaultRegistry()` — пустой реестр).
- Публичная репа жанрово-нейтральна: жанровые пакеты, их компоненты, примеры и лексика живут вне этой репы, поверх `@trempel/*` по имени.
- Рендер-агностичное ядро: логика не знает про PixiJS, общается через `RendererBackend`.
- База стерильна: `tml:*` живут только в наследнике; редактор правит базу, клипы (md) и в наследнике — только эффекты (`heir.setAttr`, `heir.insertFx`); сцена-наследник без своей базы открывается с базой только на чтение.
- Сборки кита (любой таргет) снимают метаданные с растров без перекодирования; гейт `E_ASSET_METADATA` — метаданные или сайдкары генерации (`*.png.json`, json с `prompt`/`workflow`) в dist (`packages/kit/src/vite/metadata.ts`). Провенанс — только в приватных исходниках.
- Кит 2.0: плагин Vite собирает сцены игры и её коллекций (замыкание `<use>`/`tml:extends`) в таблицу `globalThis.TREMPEL_SCENE_TABLE` (инжект перед кодом игры; в имени нельзя `__trempel` — гейт стерильности) — префабы в экранах без настройки; `?clips=<сцена>` — md-клипы при сборке с проверкой целей. Сейв — одно хранилище, два пространства: `sfx`/`music`/`svc` кита в корне, данные игры (`game.save`) — в `game`; сейв 1.x делится при загрузке. Попап забирает ввод, пока открыт (не пока закрывается). `game.destroy()` снимает всё.
- Слот: кит не считает выигрыши — только показывает ленту; ядро ленты валидируется, игровые трансформы/флаги идут сквозь; презентация — хореография данными, привязки событий — данные игры (не имена в коде плеера). gsap в код `@trempel/slot` не импортируется (он peer pixi-reels; его инстанс ведёт петля игры).
- Сервисы: объявить контракт без мока нельзя; в dev (HMR, `__TREMPEL_DEV__`) повторный `contract()` заменяет контракт, в сборке — ошибка; `Platform`, `game.platform/save/ads` — фасады над контрактами (старые игры не меняются); dev-панель и `localStorage` моков в youtube-сборку не попадают (гейт `trempel-services`).
